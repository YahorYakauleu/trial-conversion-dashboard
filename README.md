# Trial → Paid dashboard

Дашборд конверсии триальных подписок в платные для Stripe и Solidgate. Данные берутся напрямую из API провайдеров, складываются в локальную SQLite и обновляются раз в сутки.

**Что считаем** (коротко с примером — [public/metrics.md](public/metrics.md), он же открывается в дашборде по кнопке «Как считается»; решения — в [спеке](docs/specs/2026-10-12-trial-conversion-dashboard-design.md)):
- **Когорта** — триалы, оформленные в день D по времени `TIMEZONE` (по умолчанию America/New_York — как в Stripe и Campaignswell), начиная с `HISTORY_FROM`. Отменённые во время триала входят в знаменатель.
- **Сконвертилось** — первый платный инвойс оплачен в течение `RETRY_WINDOW_DAYS` (30) дней после конца триала, с любой попытки.
- **Из них с первой попытки** — оплачен первой автоматической попыткой.
- Пока по дню ещё идут триалы или ретраи, цифра растёт: в таблице это «≈», на графике — пунктир.
- **Проходимость / decline** — по попыткам списания первого платного периода (включая ретраи): успешные (отклонённые) попытки / все попытки.
- **Рефанды** — доля сконвертившихся, кому вернули первый платёж.
- **Разрезы:** страна карты, способ оплаты (Apple Pay / Google Pay / карта), банк-эмитент (только Solidgate — Stripe его не отдаёт), платёжная система, причины отказа (коды Stripe и Solidgate сведены к общим названиям). Клик по строке разреза — фильтр и динамика по этому значению; активные фильтры — чипами над карточками.
- **Темы:** светлая, тёмная и «как в системе» — переключатель в шапке, выбор хранится в браузере.

**Источники:** Stripe (любые аккаунты из `STRIPE_KEYS`) и Solidgate Reports API (каналы из `SOLIDGATE_KEYS`).

## Ключи

- **Stripe:** в каждом нужном аккаунте (Toggle Org, Toggle Corp, …) создать restricted key с правами **Read** на Subscriptions, Invoices и Events.
- **Solidgate:** public и secret key мерчантов `sg` и `sgH2H` с доступом к Reports API.

Ключи вписываются в `.env`, файл не коммитится.

## Локальный запуск

Нужен Node ≥ 22.13 (используется встроенный `node:sqlite`).

```bash
cp .env.example .env   # вписать ключи и пароль BASIC_AUTH_*
npm install
npm run dev            # http://localhost:3000, логин/пароль из BASIC_AUTH_*
```

При первом запуске сервер сам начинает догрузку истории с `HISTORY_FROM`:
- прогресс виден в логе;
- прерывать безопасно — после перезапуска продолжит с того же дня;
- Solidgate `sgH2H` с 1 сентября — около минуты; Stripe Corp — подписки ~20 минут, инвойсы и списания (попытки оплаты, ~15 тыс. в сутки) — ещё около получаса.

Если поменял `HISTORY_FROM` или список аккаунтов, останови сервер и удали папку `data/`, иначе останутся старые данные и курсоры.

Дальше синк идёт по `SYNC_CRON` (по умолчанию 05:00 UTC), по кнопке «Обновить» и при старте сервера, если последний успешный синк был больше суток назад (например, ноутбук был выключен в 05:00).

Другие команды:

```bash
npm run sync        # разовый синк без сервера, в конце — таблица статусов
npm test            # vitest
npm run typecheck
```

## Docker

```bash
docker build -t trial-dashboard .
docker run -p 3000:3000 --env-file .env -v "$(pwd)/data:/app/data" trial-dashboard
```

## Деплой

Подойдёт любой хостинг контейнеров с постоянным диском:
- volume под `/app/data` — там лежит `dashboard.sqlite`;
- переменные окружения — как в `.env.example`;
- health check — `GET /health` (без авторизации);
- все остальные роуты закрыты basic auth.

Запускать одну реплику: синк и база живут в одном процессе.
