# Trial → Paid dashboard

Дашборд конверсии триальных подписок в платные для Stripe и Solidgate. Данные берутся напрямую из API провайдеров, складываются в локальную SQLite и обновляются раз в сутки.

**Что считаем** (коротко с примером — [public/metrics.md](public/metrics.md), откуда берутся данные и как связываются — [public/data-sources.md](public/data-sources.md); оба открываются в дашборде по кнопке «Как считается»; решения — в [спеке](docs/specs/2026-10-12-trial-conversion-dashboard-design.md)):
- **Когорта** — триалы, оформленные в день D по времени провайдера, как в его кабинете: Stripe — `TIMEZONE` (по умолчанию America/New_York — как в Stripe и Campaignswell), Solidgate — `SOLIDGATE_TIMEZONE` (по умолчанию UTC — как в Solidgate Hub), начиная с `HISTORY_FROM`. Отменённые во время триала входят в знаменатель.
- **Сконвертилось** — первый платный инвойс оплачен в течение `RETRY_WINDOW_DAYS` (30) дней после конца триала, с любой попытки.
- **Из них с первой попытки** — оплачен первой автоматической попыткой.
- Пока по дню ещё идут триалы или ретраи, цифра растёт: в таблице это «≈», на графике — пунктир.
- **Проходимость / decline** — по попыткам списания первого платного периода (включая ретраи): успешные (отклонённые) попытки / все попытки.
- **Рефанды** — доля сконвертившихся, кому вернули первый платёж.
- **Разрезы:** аккаунт (Stripe Corp / Org / … и каналы Solidgate), страна карты, способ оплаты (Apple Pay / Google Pay / карта), банк-эмитент (только Solidgate — Stripe его не отдаёт), платёжная система, причины отказа (коды Stripe и Solidgate сведены к общим названиям). Клик по строке разреза — фильтр и динамика по этому значению; активные фильтры — чипами над карточками.
- **Оборот** (экран «Оборот») — все успешные списания по дню платежа в USD: оборот, рефанды, оборот без рефандов, платежи, средний чек; доля в обороте по MID (Stripe — аккаунт, Solidgate — MID заказа), стране, способу оплаты, банку и платёжной системе. Платежи Solidgate не в USD пересчитываются по дневному курсу.
- **Темы:** светлая и тёмная — переключатель в шапке, выбор хранится в браузере; без выбора — как в системе.

**Источники:** Stripe (любые аккаунты из `STRIPE_KEYS`) и Solidgate Reports API (каналы из `SOLIDGATE_KEYS`).

## Ключи

- **Stripe:** в каждом нужном аккаунте (Toggle Org, Toggle Corp, …) создать restricted key с правами **Read** на Subscriptions, Customers, Payment Methods, Invoices, Charges, Refunds и Events.
- **Solidgate:** public и secret key мерчантов `sg` и `sgH2H` с доступом к Reports API.

Ключи вписываются в `.env`, файл не коммитится.

## Локальный запуск

Нужен Node ≥ 22.13 (используется встроенный `node:sqlite`).

```bash
cp .env.example .env   # вписать ключи и пароль BASIC_AUTH_*
npm install
npm run dev            # http://localhost:3000, логин/пароль из BASIC_AUTH_*
```

При первом запуске сервер сам начинает догрузку истории с `HISTORY_FROM`:
- прогресс виден в логе;
- прерывать безопасно — после перезапуска продолжит с того же дня;
- Solidgate `sgH2H` с 1 сентября — около минуты; Stripe Corp — подписки ~20 минут, инвойсы и списания (попытки оплаты, ~15 тыс. в сутки) — ещё около получаса.

База, выгруженная до появления оборота, при следующем синке один раз заново проходит списания Stripe и заказы Solidgate с `HISTORY_FROM` — чтобы сохранить платежи. Это порядка 10–15 минут на неделю истории по всем аккаунтам Stripe (с 1 сентября — около полутора часов), потом синк снова идёт секунды.

Если поменял `HISTORY_FROM` или список аккаунтов, останови сервер и удали папку `data/`, иначе останутся старые данные и курсоры.

Дальше синк идёт по `SYNC_CRON` (по умолчанию 05:00 UTC), по кнопке «Обновить» и при старте сервера, если последний успешный синк был больше суток назад (например, ноутбук был выключен в 05:00). Ежедневный синк забирает только новое: Stripe Corp — около 2 минут, повторный запуск — секунды; Solidgate — до минуты.

Другие команды:

```bash
npm run sync        # разовый синк без сервера, в конце — таблица статусов
npm test            # vitest
npm run typecheck
```

## Посмотреть базу

Файл `data/dashboard.sqlite` (SQLite) можно открыть в DBeaver или `sqlite3 -readonly`. Время хранится в unix-секундах (`trial_started_at`, `paid_at`, …), а рядом есть вычисляемые колонки с обычной датой по UTC — `trial_started_utc`, `trial_ended_utc`, `paid_utc`, `attempted_utc`, `started_utc`/`finished_utc` у синков, `value_utc` у курсоров. Они не занимают места и считаются при чтении. Сутки в дашборде режутся по часовому поясу провайдера (Stripe — Нью-Йорк, Solidgate — UTC).

## Docker

```bash
docker build -t trial-dashboard .
docker run -p 3000:3000 --env-file .env -v "$(pwd)/data:/app/data" trial-dashboard
```

## Деплой

Подойдёт любой хостинг контейнеров с постоянным диском:
- volume под `/app/data` — там лежит `dashboard.sqlite`;
- переменные окружения — как в `.env.example`;
- health check — `GET /health` (без авторизации);
- все остальные роуты закрыты basic auth.

Запускать одну реплику: синк и база живут в одном процессе.
