# Экран Visits — дизайн

Дата: 2026-10-29 · Автор: Yahor Yakauleu · Статус: согласован в обсуждении, реализован сразу

## 1. Цель

Показать в дашборде уникальные визиты на пейволл из сборщика (visit-collector, https://collector.billpulse.app): сколько, когда, с каких сайтов и страниц, с каких устройств.

## 2. Откуда данные

Лендинг отправляет событие `visit` один раз на браузер, когда заставка ушла и пейволл на экране. Сборщик хранит только счётчики «сутки (America/New_York) × событие × разрезы» и отдаёт их по `GET /api/stats?from&to&event=visit&group=<разрез>&<фильтры>` под Bearer-токеном. Разрезы: `site`, `path` (без query-строки), `device`, `os`; `country` всегда пуст (DNS не за Cloudflare) — его на экране нет. Боты сборщик отсекает сам (`bots`); на экране их нет (решение 29.10 — после первой версии с карточкой Bots filtered).

## 3. Решение

- **Экран** «Visits» в VPN после Volume. Без провайдера и без выгрузки CSV (поштучных записей нет).
- **Карточки:** Unique visits за период, Avg. per day.
- **Trend:** таблица и столбчатый график по дням / неделям / месяцам; дни без визитов — нулями.
- **Вкладки-разрезы:** Domains (`site`), Devices, OS, Browsers (с 29.10: сборщик определяет браузер по User-Agent, встроенные браузеры соцсетей — отдельно) — с долей; клик по строке — фильтр и тренд, как на других экранах. Фильтры слева — те же разрезы, значения — из сборщика. Pages (путь) убрана 29.10: путь почти всегда «/», вкладка неинформативна.
- **Период «All»** начинается с первого дня, когда в сборщике есть данные, а не с HISTORY_FROM.
- **Сервер:** `src/visits.ts` — клиент к сборщику (кэш ответа на минуту: сборщик пишет на диск раз в минуту; таймаут 10 с) и сборка ряда / разбивки. Токен только на сервере. Отчёт асинхронный; `/api/visits`, значения фильтров (`/api/values?mode=visits`) и MCP ждут его ответа.
- **Сборщик недоступен** — только этот экран отвечает 502 с текстом ошибки; остальные экраны не затронуты.
- **Включение:** `VISITS_URL` + `VISITS_TOKEN` (= READ_TOKEN сборщика), задаются вместе. Без них экрана, API и инструмента MCP нет.
- **MCP:** инструмент `visits`, `filter_values` с `mode=visits`.
- **Методология:** раздел Visits; источники данных — сборщик.

Не делаем: «Визит → Триал» — триалы Funnelfox идут мимо пейволла, визит и триал одного человека — в разные дни, у триала нет сайта. Честная конверсия — после события триала или id посетителя в подписке.

## 4. Тесты

- Конфиг: обе переменные или ни одной; без токена в тексте ошибки.
- Клиент: адрес запроса, токен в заголовке, кэш, ошибка сборщика без токена в тексте.
- Ряд по дням / неделям / месяцам с нулевыми днями; разбивка с долей, «не определено» — в конце.
- API: экран и значения фильтров с подменённым клиентом; 502, когда сборщик недоступен; 404 без настроек; неверное значение фильтра отбрасывается.
- MCP: инструмент `visits` есть только при подключённом сборщике.
