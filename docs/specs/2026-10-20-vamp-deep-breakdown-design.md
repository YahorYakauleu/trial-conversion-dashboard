# VAMP — детальная разбивка для поиска паттернов — дизайн

Дата: 2026-10-20 · Автор: Yahor Yakauleu · Статус: утверждён в обсуждении, ждёт ревью спека

## 1. Цель

На вкладке VAMP искать, откуда берутся фрод-репорты и чарджбэки Visa: какие банки, типы карт, номера платежей подписки, кампании и лендинги дают ratio заметно выше среднего. Копать вглубь — последовательными кликами: строка разреза становится фильтром для всех вкладок.

## 2. Скоуп

**Входит**
- Новые вкладки-разрезы: Issuing banks, Card types, Payment number, Reasons, Days to report, Traffic sources, Campaigns, Landing domains.
- Колонка «× к среднему» и подсветка аномальных строк.
- Фильтр по любому разрезу VAMP (сейчас — только мерчант, MID, страна, способ оплаты).
- Новые колонки в CSV-выгрузке событий.
- Вкладка Charge type убирается — её заменяет Payment number.

**Не входит**
- Сводная таблица двух разрезов и автопоиск сегментов (подходы B и C) — можно добавить поверх позже, данные те же.
- Разбивка по кампаниям и лендингам на экранах триалов (Conversion, LTV и др.).
- Атрибуция трафика у Solidgate — в заказах её нет (`order_metadata` и `traffic_source` пусты).
- Цена или план подписки как разрез (в metadata подписки Stripe есть `price` — кандидат на потом).

## 3. Разрезы

Все строки — за месяц, как сейчас (последний месяц выбранного периода, события по дате прихода в Stripe/Solidgate, UTC). Сумма VAMP count по строкам любой вкладки = VAMP count месяца.

| Вкладка | Значение строки | Ratio |
|---|---|---|
| Trend, Merchants, MID, Countries, Payment methods, After report, Radar risk | без изменений | как сейчас |
| Issuing banks | банк карты списания, в одном написании (`bankName`) | да |
| Card types | debit · credit · prepaid | да |
| Payment number | Trial fee · 1st after trial · 2nd · 3rd · 4th · 5+ · Before history | да |
| Reasons | репорт: тип фрода (`unauthorized_use_of_card`, `made_with_counterfeit_card`, `made_with_lost_card`…); чарджбэк: причина диспута (`fraudulent`, `subscription_canceled`…) — с понятными подписями | нет |
| Days to report | 0–7 · 8–30 · 31–60 · 61–90 · 91–180 · 180+ дней от списания до события | нет |
| Traffic sources | `utm_source` клиента Stripe (voluum, affise) | да |
| Campaigns | `campaign_id` клиента Stripe, подписан `campaign_name` (без имени — только ID) | да |
| Landing domains | домен из `url` клиента Stripe, без `www.` | да |

Значение, которого нет у события, — строка Unknown в конце (как сейчас). События Solidgate на вкладках трафика — Unknown.

**Payment number.** Платёж относится к последнему триалу клиента, оформленному не позже платежа (с запасом `TOLERANCE` = 1 ч, как в LTV), и не дальше следующего триала клиента. Платёж до конца триала (минус `TOLERANCE`) — Trial fee; после — 1, 2, 3… по порядку. Клиент без триала в истории (подписка оформлена до `HISTORY_FROM`) — Before history; событие по списанию, которого нет в платежах дашборда (списание раньше истории), — тоже Before history. Только VPN-платежи.

**Days to report** = день события − день списания (`reported_at − charged_at`, целые сутки). Границы включительно: ≤ 7, ≤ 30, ≤ 60, ≤ 90, ≤ 180, дальше 180+. Без даты списания — Unknown.

## 4. Метрики строки

- VAMP count, доля от count месяца, RDR — как сейчас.
- Visa sales и VAMP ratio — у разрезов, которые есть и у продаж (колонка «Ratio» в таблице выше).
- **× к среднему** = ratio строки ÷ ratio всей выборки (тот же месяц, те же фильтры). Нет ratio — нет и множителя.
- **Подсветка** строки: × к среднему ≥ 2 и VAMP count ≥ 10.

## 5. Фильтры

- Фильтром становится каждый разрез VAMP (клик по строке — как сейчас). Число у значения в списке фильтра — VAMP count текущей выборки.
- Фильтр по разрезу без продаж (Reasons, Days to report, Radar risk) скрывает ratio и × к среднему — продажи по нему не отфильтровать (так уже работает Radar risk).
- Статус Excessive / At risk — только у мерчанта целиком, без фильтров кроме мерчанта (без изменений).

## 6. Данные

### 6.1 У события (`vamp_reports`)

Новые колонки: `bank`, `funding`, `utm_source`, `campaign_id`, `campaign_name`, `landing_domain`.

- **Stripe:** из списания и клиента, которые приходят вместе с фрод-репортом и диспутом (`expand: data.charge, data.charge.customer`). Есть и у списаний раньше истории.
- **Solidgate:** колонки пусты; банк и тип карты берутся из платежа дашборда (заказ), как сейчас страна и MID.
- В запросах значение события — `COALESCE(v.<поле>, p.<поле>)`.

### 6.2 У платежа (`payments`)

Новые колонки: `funding`, `utm_source`, `campaign_id`, `campaign_name`, `landing_domain`, `payment_n`.

- **Stripe:** тип карты — из списания (`payment_method_details.card.funding`), атрибуция — из metadata клиента; инкрементальный синк списаний разворачивает клиента (`expand: data.customer`).
- **Solidgate:** тип карты — из заказа (`card.card_type`), атрибуции нет.
- **`payment_n`** — номер платежа (§ 3): `0` — Trial fee, `1…` — после триала, `-1` — Before history, `NULL` — ещё не посчитан. Считается заранее, после загрузки платежей аккаунта (для ещё не посчитанных); целиком — один раз при появлении колонки и при сдвиге `HISTORY_FROM` раньше (у старых платежей появляются триалы). Экраны берут готовое значение.

### 6.3 Нормализация

- `utm_source` — нижний регистр, без пробелов по краям (`Affise` → `affise`).
- `landing_domain` — только hostname из `url`, нижний регистр, без `www.`; путь и строка запроса не хранятся (в них бывают click ID). Неразбираемый `url` — пусто.
- `campaign_name` — как есть; подпись кампании — самое частое имя у её ID.
- Не храним: `ip_address`, `user_id`, `ga_user_pseudo_id`, полный `url`.

## 7. Разовые загрузки

Идут сами при ближайшем синке после деплоя, прогресс сохраняется, лимит запросов Stripe повторяется (`forEachWindow`).

| Что | Как | Время на проде |
|---|---|---|
| События VAMP Stripe | `VAMP_VERSION` 3: перезагрузка с `HISTORY_FROM` неделями, с клиентом списания | минуты (~28 тыс. событий) |
| Тип карты и атрибуция продаж Stripe | `PAYMENT_CUSTOMERS_VERSION` 3: поиск успешных списаний с `HISTORY_FROM` с клиентом, дописываются только пустые поля | ~1,5–2 ч |
| Тип карты продаж Solidgate | `ORDERS_VERSION` 5: повторный проход заказов с `HISTORY_FROM` | минуты |
| Номер платежа | пересчёт при открытии базы, если колонки ещё нет | секунды |

Пока проход по продажам не закончен, у Card types и вкладок трафика знаменатель неполный — ratio завышен. Это одна ночь; в методологии — одна строка, отдельного предупреждения в интерфейсе нет.

## 8. Выгрузка

CSV событий VAMP получает колонки: `issuing_bank`, `card_type`, `payment_number`, `days_to_report`, `utm_source`, `campaign_id`, `campaign_name`, `landing_domain`.

## 9. Скорость

Все новые значения хранятся у события и платежа, номер платежа посчитан заранее. Перед пушем — замер всех вкладок VAMP «за всё время» на локальной базе: ориентир меньше секунды на вкладку. Если какая-то медленнее — индекс под неё.

## 10. Тесты

- Каждый новый разрез на фикстуре: события, продажи, ratio; сумма строк = VAMP count месяца.
- Payment number: Trial fee; 1-й, 2-й…; новый триал клиента начинает нумерацию заново; клиент без триала — Before history; событие по списанию вне истории — Before history.
- Days to report: границы корзин (7, 30, 60, 90, 180).
- × к среднему и подсветка: порог 2× и 10 событий; без ratio — без множителя.
- Фильтр по разрезу без продаж скрывает ratio.
- Атрибуция: домен без `www.` и без пути; `utm_source` в нижнем регистре; пустые поля и Solidgate — Unknown; `ip_address`/`user_id` не попадают в базу.
- Разовые загрузки: выполняются один раз; прерванная продолжает с сохранённого дня; известные значения не затираются.
- Выгрузка: новые колонки.

## 11. Ограничения

- **Payment number у старых подписок.** Сейчас около половины событий Stripe — продления подписок, оформленных до 1 июля: у них Before history. Доля падает с каждым месяцем истории. Банк, тип карты, страна, причины и трафик есть у всех событий Stripe.
- **Пустая атрибуция.** У части клиентов поля пусты (org — ~30% новых клиентов; у трафика Affise нет `campaign_name`) — строка Unknown.
- **Атрибуция только у Stripe.**

## 12. Документация

Методология VPN (раздел VAMP) — новые разрезы, × к среднему, Payment number и его ограничение, атрибуция только у Stripe, строка о первой ночи после деплоя. Подсказки к вкладкам и колонкам в интерфейсе.
